# 思源能力盘点（v3.8.6）

2026-10-29。依据：本机内核 CLI 全命令帮助、内核二进制里的 HTTP 路由、实时 API 调用、`blocks` 表结构。

本机环境：`/Applications/SiYuan.app`，内核 `SiYuan-Kernel v3.8.6`，13 个笔记本，41322 个块，4 万+ 文档块。

---

## 零、结论先行

思源有三层入口，能力比预想的完整得多：

1. **CLI**：`~/.local/bin/siyuan` 直接指向内核二进制，30 多个子命令
2. **HTTP API**：126 条路由，覆盖块、属性、数据库、引用、快照、导出、AI
3. **SQL**：只读，直接查 `blocks` 表
4. **MCP server**：`http://127.0.0.1:6806/mcp`，30 个工具，实测调通

**它什么都给了，只缺一样：从别的应用里采集内容。** 检索、写入、语义、重排、agent 循环、技能、会话，全都有。

所以最终形态比之前的设计小得多：`mem` 只负责"读 DSH 日志 → 抽取 → 调 MCP 写入"，插件只负责注入。查询和写入的代码是**零**。

## 一、CLI（内核自带，不需要额外装）

`~/.local/bin/siyuan` → `/Applications/SiYuan.app/Contents/Resources/kernel/SiYuan-Kernel`

通用参数：

| 参数 | 作用 |
|---|---|
| `-f, --format` | `table` 或 `json` |
| `-w, --workspace` | 指定工作区 |
| `--dry-run` | 只校验并打印，不落盘 |

### 命令表

**查询**
- `sql <statement> [-l limit]` — 只读 SQL
- `search <query>` — 全文 / 语义 / 资源内文

**块**
`block append --parent <id> --data <md> | --file -`、`get`、`batch-get`、`children`、`breadcrumb`、`dom`、`delete`、`batch-kramdown`

**属性**
`attr set --id <id> --attr k=v`（可重复）、`get`、`batch-get`

**文档**
`document create --notebook <id> --title <t> --markdown <md> --path /`、`list`、`get`、`info`、`rename`、`move`、`remove`、`duplicate`

**数据库（属性视图）**
`database item add --av <avID> [--content] [--block <id>] [--detached]`、`item update`、`item remove`、`key`、`keys`、`get`、`render`、`search`

**引用**
`ref backlinks <id>`、`ref mentions`、`ref refresh`

**笔记本**
`notebook list / create / rename / remove / open / close / set-icon`

**导出**
`export md / docx / html / sy / md-zip / preview / data`

**快照**
`repo create / list / diff / checkout / search / tag / purge`

**其它**
`file`（read / grep / list / stat / copy / rename / delete）、`asset`（upload / unused / clean / stat）、`history`、`import`、`template`、`tag`、`bookmark`、`outline`、`dailynote`、`inbox`、`sync`、`system current-time`

### 一个坑

CLI 启动时会重写 `~/.config/siyuan/workspace.json`。我的沙箱不允许写那个目录，所以**所有需要真正执行的命令我都跑不通**（`--help` 能跑）。加 `-w` 也绕不过，因为写 workspace 列表发生在 init 阶段。

你本机终端应该正常。这条要你验证一次。

## 二、HTTP API（126 条路由）

从内核二进制里提取，按域分布：

| 域 | 数量 | 代表 |
|---|---|---|
| system | 16 | version、getConf、getWorkspaceStorage、rebuildDataIndex |
| notebook | 10 | lsNotebooks、createNotebook、renameNotebook |
| block | 10 | appendBlock、insertBlock、updateBlock、deleteBlock、prependBlock |
| av | 6+ | addAttributeViewKey、createAttributeViewItem、setAttributeViewBlockAttr、renderAttributeView、searchAttributeView |
| search | 3 | fullTextSearchBlock、semanticSearchBlock、searchRefBlock |
| ai | 3+ | testEmbeddingModel、reindexEmbedding、embeddingStat、testRerankModel、agent/* |
| sync / repo / history / broadcast / archive / setting | 各 2-4 | — |
| query | 2 | sql、syncPending |
| mcp | 4 | addOAuthClient、getOAuth、setOAuth、removeOAuthClient（是客户端，不是服务端） |

**关键三条：**

- `/api/query/sql` — 只读查询
- `/api/block/appendBlock` — 追加块
- `/api/attr/setBlockAttrs` — 写自定义属性

### 写接口是静默失败的

实测 `UPDATE`、`CREATE TABLE` 走 `/api/query/sql`，都返回 `{"code":0,"msg":""}`，但**什么都没发生**。

SQL 接口只执行 SELECT。不报错、不提示、不生效。这是最容易踩的坑——你会以为写入成功了。

## 三、SQL 与数据模型

### blocks 表（实测 schema）

```sql
CREATE TABLE blocks (
  id, parent_id, root_id, hash, box, path, hpath,
  name, alias, memo, tag, content, fcontent, markdown,
  length, type, subtype, ial, sort, created, updated
)
```

对我们有用的字段：

| 字段 | 用途 |
|---|---|
| `id` | 块 id，做索引主键 |
| `root_id` | 所属文档 |
| `box` | 笔记本 id |
| `type` | `d`=文档 `p`=段落 `h`=标题 `av`=属性视图 … |
| `content` | 纯文本（搜索用这个） |
| `markdown` | 原始 markdown |
| `alias` / `memo` / `tag` | **三个现成的元数据位**，不用占 custom-* |
| `ial` | 内联属性 JSON，`custom-*` 全在这里 |
| `created` / `updated` | 时间戳 |

### 自定义属性的真实存法

`custom-xxx` 不在独立表里，是塞进 `ial` 字段的 JSON。所以：

```sql
SELECT * FROM blocks WHERE ial LIKE '%custom-status%'
```

能查到，但要解析 JSON。79 个块已经用了 custom-*。

### 属性视图

全库只有 1 个 `av` 块 —— 说明这套东西你用得不深。要做记忆索引表，得新建一个，走 `database` 命令族。

## 四、三个意外发现

### 1. 语义检索和 rerank 是内置的，只是没开

实测：

```
/api/ai/embeddingStat →
{ total: 41322, indexed: 0, pending: 41322, failed: 0, enabled: false }
```

`/api/search/semanticSearchBlock` 存在，返回 0 条；`/api/ai/testEmbeddingModel`、`/api/ai/testRerankModel`、`/api/ai/reindexEmbedding` 都在。

**意思是：前面设计的"自己上 sqlite-vec + bge + bge-reranker"，可能整块可以删掉。** 只要在设置里配好 embedding 模型、把索引建起来，思源自己就能做语义检索 + 重排。

代价要说清楚：41322 个块全量 embedding，要么走云端 API（花钱、内容出本机），要么配本地模型（占内存、建索引要跑很久，而且 app 必须开着）。

### 2. 思源自己带一个 agent

`/api/ai/agent/*`：chat、sessions、skills、instructions、permissions、browserCapability。

也就是说它能内置一个 agent 循环。但那是编辑器窗口里的，跟着窗口活着，不是我们的路。

### 3. blocks 表有三个白送的元数据位

`alias`、`memo`、`tag`。在思源界面里分别对应"别名""备注""标签"，模型能直接看到，人也能直接看到。

这比全塞 `custom-*` 好：`custom-*` 要进属性面板才看得见，`alias`/`tag` 在正文和反链里都露头。

## 五、能力边界（思源做不到的）

| 做不到 | 原因 |
|---|---|
| 采集会话日志 | 跟它无关，是 harness 的事 |
| 定时调度 | 插件生命周期绑窗口（官方 plugin-sample：退出应用不触发插件钩子）；Docker 版内核有 10 分钟级定时但只给同步用 |
| 用大模型做整理 | 自带 AI 是编辑器作用域，看不见笔记本列表，没有自主性 |
| 通过 SQL 写入 | 只读，且静默失败 |
| 语义检索免配置 | 需手动开启 + 建索引 + app 常驻 |
| 定义"记忆"这个概念 | 它只有块、属性、引用，没有状态机 |

## 六、对方案的影响

原来的设计里，有几块可以直接删：

| 原计划 | 现在 |
|---|---|
| 自己写 HTTP client 读写思源 | 删。shell 出去调 `siyuan` CLI |
| 自己维护 SQL 模板（`mem search`） | 大幅缩小。`siyuan search` 已有 `-m/-o/-t/--path/-n` |
| 自己上 sqlite-vec + onnx embedding | 可能删。思源内置语义检索 |
| 自己上 bge-reranker | 可能删。`/api/ai/testRerankModel` 说明有内置重排 |

留下的只有三件，都是思源没有的：

1. **读 DSH 会话日志，按规则过滤**（thinking / 工具调用 / 注入内容全丢）
2. **调便宜模型把段落压成条目**
3. **去重合并后调 `siyuan` 写入**

再加一个 40 行的 DSH 插件，只做 `agent/pre-step` 注入。

## 九、AI 能力实测（2026-10-29 补）

结论：**它已经把"AI 用你的笔记"这件事做完了，做得很深。**

### 时间线

| 版本 | 日期 | 内容 |
|---|---|---|
| v3.7.0 | 2026-06-30 | "AI knowledge base"：SiYuan Agent + 向量检索进入公测 |
| v3.8.0 | 2026-08-12 | "AI-powered knowledge management"：语义搜索（embedding + reranking）、AI Agent 正式、**MCP support** |

### 一、MCP server：30 个工具，实测可用

`POST http://127.0.0.1:6806/mcp`，streamable HTTP，协议 `2025-06-18`，`serverInfo: {name: "SiYuan", version: "3.8.6"}`。

流程：`initialize` → 拿 `Mcp-Session-Id` → `tools/list` / `tools/call`。

工具清单（30 个）：

`asset` `attr` `bazaar` `block` `bookmark` `dailynote` `database` `document` `export` `file` `history` `http_request` `image` `import` `inbox` `notebook` `outline` `ref` `repo` `search` `skill` `sql` `sync` `system` `tag` `template` `unzip` `web_fetch` `web_search` `workspace`

实测两个调用，都通：

```
tools/call sql      {action:"query", stmt:"SELECT count(*) FROM blocks"}  →  返回 markdown 表格
tools/call notebook {action:"list"}                                       →  13 个笔记本
```

**这意味着：DSH 只要配一个 MCP 地址，读写思源的代码是零。**

### 二、内置 AI Agent：34 个原生能力

`/api/ai/lsCapabilities` 返回 34 个能力，全部 `native/kernel` 运行时：

`asset` `attr` `bazaar` `block` `bookmark` `dailynote` `database` **`decision`** `document` `export` `file` `history` `http_request` `image` `import` `inbox` `log` `notebook` `outline` **`question`** `ref` `repo` `search` **`skill`** `sql` `sync` `system` `tag` `template` **`todo_write`** `unzip` `web_fetch` `web_search` `workspace`

其中几个是 agent 专用件，说明它是个完整 agent 而不只是聊天框：

- `decision` — TypeSafe System One 决策模型，批量分类/筛选/打分，最多 255 个选项
- `question` — 向用户提问澄清，带选项和自定义输入
- `todo_write` — 会话任务清单
- `skill` — 加载/保存/安装技能（和 Claude Skills 一个思路）

会话、指令、权限也齐：`agent/lsSessions`、`agent/getInstructions`、`agent/setPermission`。

### 三、触发方式：SSE 流式，外部可调

`POST /api/ai/agent/chat` 返回 SSE 事件流。空 body 也起了一个 turn：

```
event:turn      {"turnID":"..."}
event:thinking  {"reasoning":"analyzing", ...}
event:error     {"message":"网络超时，请稍后再试"}
```

最后报错是因为**没配模型**：`conf.ai` 是空对象，`/api/ai/listModels` 返回 `provider not found`。

### 四、语义检索：管道齐了，开关没开

`/api/ai/embeddingStat`：

```
{ total: 41322, indexed: 0, pending: 41322, failed: 0, enabled: false }
```

`/api/search/semanticSearchBlock` 存在、返回空；`siyuan search -m 4` 同样空。要开就得配 embedding 模型 + 建索引。

## 十、所以"人家做了没有"

| 事项 | 状态 |
|---|---|
| 用 AI 检索笔记 | 做了（语义 + 关键词 + 资源内文） |
| 用 AI 改笔记（增删改块、建数据库、打标签） | 做了（34 个能力 / 30 个 MCP 工具） |
| AI 帮你整理某一篇/某一堆笔记 | 做了（agent 会话里手动指挥） |
| 外部 agent 接进来用 | 做了（MCP server） |
| **自动从别的应用采集内容** | **没做，也不可能做**——它看不见 DSH 的会话 |
| **无人在场时定时触发** | 没做（agent 要人开） |
| **记忆的状态语义**（current / superseded / 衰减） | 没做，它只有块和属性，没有状态机 |

**最后三行就是 `mem` 的全部工作。**

## 十一、两个新风险

**一、MCP 无鉴权就等于把整个知识库敞开。** 本机 `127.0.0.1:6806/mcp` 我直接连上了，不需要 token。也就是说**这台机器上任何一个程序都能无密码读写你全部笔记**。局域网访问要另配 token，但本机这条口子默认是开的。

**二、配了 AI 模型 = 笔记内容会发出去。** 内置 agent 的 `decision`、`search` 都会把块内容送到外部模型。它自己的能力描述里写得很直白："Sends content externa…"（发送到外部）。

这两条不是要你别用，是别糊里糊涂地开。
